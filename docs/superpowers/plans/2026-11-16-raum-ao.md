# Raum-AO (GTAO auf WebGPU) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Soft corner darkening (GTAO) in the room on WebGPU at "Mittel" and "Hoch", with MSAA intact, photos untouched and the ceiling as bright as without AO.

**Architecture:** A pure module `src/lib/ambientOcclusion.ts` decides whether AO runs (quality flag, renderer, view mode, URL override) and holds the AO values (Vitest). `webgpuSupport.ts` builds the TSL pipeline: the multisampled scene pass for colour, a separate non-multisampled half-resolution depth pass for GTAO + denoise, and a depth pass of the artwork layer that masks photos/videos out. `RoomAmbientOcclusion` (in `Scene`) owns the pipeline and renders the frame at `useFrame` priority 1 while it is on.

**Tech Stack:** three r186 TSL (`RenderPipeline`, `pass`, `ao`, `denoise`, `getNormalFromDepth`), @react-three/fiber 9, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-raum-ao-design.md`

## Global Constraints

- WebGPU only (`isWebGPURenderer(gl)`); WebGL renders exactly as today. Never import `three/webgpu` or `three/tsl` outside `src/lib/webgpuSupport.ts`.
- On in `medium` and `high`, off in `low`. No UI switch; `?ao=0|1` overrides for comparisons.
- Off in: 2D wall editor, AR export page, mobile planner. Offscreen renders (glass reflection etc.) never go through the pipeline.
- `tsl/display` addons stay in the `vendor-three-webgpu` chunk (`vite.config.ts`), else "Class extends value undefined" on load.
- Start values: radius 0.6 m, strength 1, resolution scale 0.5, 16 samples. Final values tuned on screenshots.
- Anti-goals: room darker/dirty/blotchy, photos or frame colours shifted, jaggies/noise/flicker when walking, ceiling over-exposed or halo around trusses, frame rate noticeably lower.
- Never run the app locally. Visual checks on the test stack (headless Chrome over CDP, `--headless=new --enable-unsafe-webgpu`). Vitest for pure modules is fine.
- Comments English, UI strings (none here) German.
- Branch `feat/room-ao` off `feat/room-shading`.

## Review Focus

1. Switching the quality preset in the running viewer (Hoch → Niedrig → Mittel) builds/tears down the pipeline without reload, black frames or a leaked render loop → Task 2 Step 6 screenshot sequence.
2. Window resize / dpr change while AO is on: AO stays aligned with the geometry (no offset halo) → Task 2 Step 6 resize check.
3. Opening the 2D wall editor while AO is on: the orthographic wall editor renders without AO and without a stale frame → Task 1 test `off while the wall editor is open` + Task 2 Step 6 screenshot.
4. Videos (VideoTexture) and splats on the artwork layer: not darkened, splat sorting unaffected → Task 3 Step 4 screenshots incl. one video.
5. First person walking: no flicker at wall edges from the half-resolution AO → Task 4 Step 2 sequence of 5 frames while moving.

### Task 2: Pipeline with MSAA + correct tone mapping, mounted in Scene

**Interfaces:**
- Consumes: `AmbientOcclusionOptions`, `AO_DEFAULTS`, `readAmbientOcclusionOverride`, `shouldRunAmbientOcclusion`, `RenderQualitySettings.ambientOcclusion` (Task 1).
- Produces:
  - `createAmbientOcclusionPipeline(gl: THREE.WebGLRenderer, scene: THREE.Scene, camera: THREE.Camera, options: AmbientOcclusionOptions): { render(): void; dispose(): void }` (exposed via `getWebGPUSupport(gl)`)
  - `RoomAmbientOcclusion(): null` — reads quality settings, `isWebGPURenderer(gl)`, `useEditorStore` (`wallEditor`, `mobilePlanner`), `useExportMode().active`, the URL override once per mount; builds the pipeline in `useMemo` keyed on (enabled, gl, scene, camera, options), disposes in `useEffect` cleanup, `useFrame(() => pipeline?.render(), pipeline ? 1 : 0)`.

- [ ] **Step 1: Pipeline structure** in `createAmbientOcclusionPipeline`:
  - Colour: `pass(scene, camera)` with the renderer's default samples (MSAA kept). Its `output` texture is the composited colour.
  - AO depth: a second `pass(scene, camera, { samples: 0 })` with `resolutionScale = options.resolutionScale` and a cheap override material (depth only, no lighting); normals from `getNormalFromDepth` on that depth, `ao()` + `denoise()` on it as in the spike.
  - Composite: `colour.rgb × mix(1, aoValue, strength)`, sampled from the half-res AO with the colour pass's UV.
- [ ] **Step 2: Ceiling bug (superpowers:systematic-debugging).** Spike symptom: at "Hoch" the ceiling clips to 255 (241 without AO) with a halo around the trusses; "Niedrig" fine. Find the cause before changing code (candidates: RectAreaLight/ceiling material bypasses the per-material tone-mapping patch inside a `PassNode`; `RenderPipeline.outputColorTransform` applying a second transform; AO halo from depth discontinuities at the trusses). Record the cause in the commit message. Acceptance: ceiling region luminance with `?ao=1` within ±3 of `?ao=0` at "Hoch" and "Mittel" (`lum.py` on the same camera pose).
- [ ] **Step 3: Component + mount.** Replace nothing else in Scene; mount `{!exportMode && <RoomAmbientOcclusion />}` after the lights. The spike component is not ported.
- [ ] **Step 4: Run** `npm run build` and `npm run lint` → clean; `npx vitest run` → all pass.
